# Жила — накрутка счётчика Spectator Gem в Dota 2

Документ переносит проект в чистую папку. До этого он лежал вперемешку с **DotaTrade**
(маркетплейс и верификация Steam-трейдов) — это два разных проекта, общего у них только Dota 2.

Каждое утверждение помечено уровнем достоверности:

- `VERIFIED` — первоисточник: бинарь клиента, протоколы Valve, схема предмета, ответ API
- `OBSERVED` — собственный живой эксперимент на аккаунте
- `HYPOTHESIS` — вывод без прямого подтверждения
- `CONFLICT` — источники расходятся

---

## 1. Что это

**Spectator Gem** (Самоцвет наблюдателя) — гем, который вставляется в косметический предмет
Dota 2 и несёт счётчик «Games Watched». `VERIFIED`

Счётчик — атрибут **самого гема**, а не предмета: голые гемы на торговой площадке показывают
разные значения, от 0 до 168. `VERIFIED`

Рыночная неэффективность, с которой всё началось: **Steam Market не умеет ценообразовать по
счётчику**. Все лоты «Spectator: BZZ» — один товар с одной ценой, и гем с 94 просмотрами стоит
столько же, сколько пустой. `OBSERVED` (полный скан 251 лота)

Отсюда задача: понять, как счётчик набивается, и можно ли это воспроизвести.

---

## 2. Главный результат

Счётчик поднимается **одним сообщением Game Coordinator**. Ни игры, ни реплея, ни просмотра
не требуется.

```
k_EMsgUpgradeLeagueItem = 7203

message CMsgUpgradeLeagueItem {
    optional uint64 match_id  = 1;
    optional uint32 league_id = 2;
}
```

`VERIFIED` — сообщение и его номер подсмотрены в `console.log` живого клиента при `playdemo`,
поля подтверждены по `dota_gcmessages_client.proto`.

Обмен выглядит так:

```
[GCClient] Send msg 7203 (k_EMsgUpgradeLeagueItem), 27 bytes
[GCClient] Recv msg 26  (k_ESOMsg_UpdateMultiple), 907 bytes   <- предметы обновились
[GCClient] Recv msg 7204 (k_EMsgUpgradeLeagueItemResponse), 17 bytes
```

Размер `msg 26` — косвенная мера того, сколько предметов подняло одно сообщение: 97 байт на
один предмет, 907 байт на тринадцать.

GC сам поднимает историю матча, смотрит его участников и повышает **все подходящие гемы в
инвентаре разом**. `OBSERVED`

Поле счётчика называется `games_viewed`, Spectator Gem — `def_index 3003`, prefab `socket_gem`,
дата создания 2013-10-31. Стили предметов разблокируются через `"unlock_field" "games_viewed"`.
`VERIFIED` — вытащено из `items_game.txt` клиента.

## 3. Как это доказано

Хронология экспериментов на живом аккаунте. Все замеры — дифф инвентаря до и после.

### 3.1 Просмотр реплея в клиенте

Скачали матч NaVi (лига 19944), запустили `playdemo`, ускорили `demo_timescale`.

Гем NaVi: **0 → 1**. `OBSERVED`

Сообщение 7203 ушло **в начале воспроизведения**, на `DOTA_GAMERULES_STATE_HERO_SELECTION`,
раньше, чем была набрана команда ускорения. Досматривать реплей не нужно. `OBSERVED`

### 3.2 Отправка сообщения ботом, без клиента

`steam-user` → логин → `gamesPlayed([570])` → `ClientHello (4006)` → дождались `ClientWelcome (4004)`
→ `sendToGC(570, 7203, {}, protobuf)`.

Пять матчей NaVi, из них один уже был засчитан реплеем. Гем NaVi: **1 → 5**, ровно четыре новых.
`OBSERVED`

### 3.3 Привязка гема — не к игроку

Отправили 10 матчей **Team Empire**. Поднялись **14 предметов одновременно**:

| Гем | Было | Стало |
|---|---|---|
| BZZ (8 частей сета) | 0 | 10 |
| Team Empire (5 предметов) | 1 | 11 |

BZZ — это Станислав «633» Глушан, он играл за Empire. Гем «игрока» засчитывается по матчам,
где этот игрок участвовал. `OBSERVED`

Гипотеза «гем считает любую игру» — **опровергнута**: на матчах NaVi гемы Empire и BZZ не
шелохнулись.

### 3.4 Дедупликация — на аккаунт, не на предмет

Повторили те же пять матчей NaVi: пять ответов `7204` и **ни одного `msg 26`**. `OBSERVED`

Купили новый гем BZZ со своим счётчиком 2, который этих матчей не видел, и повторили уже
сожжённые матчи Empire — **ноль обновлений**. `OBSERVED`

Контрольная проверка на двух свежих матчах Empire: новый гем **2 → 4**, старые восемь
**10 → 12**, Empire **11 → 13**. Значит бандлы тикают нормально, и предыдущий ноль означал
именно исчерпание матчей. `OBSERVED`

**Вывод: матч засчитывается аккаунту один раз и сгорает навсегда.**

### 3.5 Что не подтвердилось

- `CMsgGCWatchDownloadedReplay (7206)` — существует в бинарях, но счётчик поднимает не он. Была
  моя первая версия, оказалась неверной. `CONFLICT` → снято
- Steam Web API `IEconItems_570/GetPlayerItems` **счётчик не отдаёт**. Приходят `defindex`,
  `equipped`, `flag_cannot_trade` и атрибут 427 (дата трейд-кулдауна). Счётчик берётся только
  из community-инвентаря разбором описаний. `VERIFIED`
- Конвар `dota_spectator_auto_spectate_games` существует и не помечен читом («Automatically
  spectate available games. Set to a LeagueID to auto spectate games from that league»), но это
  медленный путь: примерно один матч за 30-40 минут. `VERIFIED`

### 3.6 Замеры 19–20 августа

Пять проверок на живом аккаунте. Каждая закрыла вопрос, который до этого был догадкой.

**Голый гем без сокета набирает счётчик.** `OBSERVED`
Купили `Spectator: Alliance` со счётчиком 2, отправили один матч Alliance.
Гем **2 → 3**, три предмета с сокетом **0 → 1**, остальные гемы неподвижны.
Одно сообщение подняло четыре объекта с двумя разными базами.
Artificer's Chisel не нужен — закупка упирается в гемы по три цента, а не в
чиселы по доллару, которых на рынке три штуки в сутки.

**Гем считает свою сущность, а не лигу.** `OBSERVED`
В лиге 14389 у Empire один матч, у NaVi десять. Сожгли матч Empire из этой лиги:
Empire 1 → 11, BZZ 0 → 10, **NaVi остался 5**. Будь охват лиговым, NaVi обязан
был тикнуть. Потолок гема — это матчи его сущности, и ничего сверх.

**Аккаунтный журнал GC не истекает.** `OBSERVED`
Пять матчей NaVi, сожжённых 26 часами ранее, отправлены повторно: пять ответов
7204, ноль обновлений, счётчик не двинулся. Доить одну сущность бесконечно нельзя.

**`league_id` обязателен.** `OBSERVED`
Матч 8003261364, две попытки подряд:

```
без league_id  →  7204, 0 байт, счётчик неподвижен
с league_id    →  ОБНОВЛЕНО, 507 байт, Alliance 1→2, голый гем 3→4
```

GC молча отвергает сообщение без второго поля. Это блокировало 26 гемов-игроков:
`/players/{id}/matches` у OpenDota не содержит `leagueid` вовсе, и списки для них
строились с пустой лигой.

**`dup` не означает «сожжён».** `VERIFIED` + `OBSERVED`
`CMsgUpgradeLeagueItemResponse` — **пустое сообщение**, полей нет ни одного
(проверено по протоколу Valve). Поэтому 7204 без `msg 26` означает только
«счётчика не будет», а причина может быть любой: матч израсходован, сообщение
отвергнуто, подходящих гемов не нашлось. Тот самый 8003261364 вернул `dup`
и остался целым.

**Подтверждением засчёта считается только `msg 26`.** Всё остальное — догадка.

## 4. Правила, которые из этого следуют

1. **Матч сгорает навсегда.** Гемы, купленные после прожига, уже израсходованные матчи не получат.
2. **Состав собирается до запуска.** Одно сообщение поднимает все подходящие гемы разом — значит
   сначала докупить всё, что хочешь набить, потом жечь.
3. **Потолок гема = число матчей его сущности**, минус то, что аккаунт уже сжёг.
4. **Пересечения работают на тебя.** Матчи Empire поднимают и Empire, и BZZ, потому что 633
   играл за Empire.
5. **Старость матча не мешает.** Заходили лиги 2020 года и раньше.
6. **`league_id` обязателен.** Сообщение без него уходит, GC отвечает, счётчик не двигается,
   а матч остаётся целым. Снаружи это неотличимо от дубля. Строку без лиги отправлять нельзя.
7. **Сокет не нужен.** Голый гем в инвентаре тикает наравне с гемом в предмете и с гемом
   в нераспакованном наборе. Одно сообщение поднимает все подходящие экземпляры разом,
   по единице каждому, независимо от их текущего значения.
8. **Верить только `msg 26`.** Ответ 7204 пуст по протоколу и не различает дубль и отказ.
   Локальный журнал, помечающий матч сожжённым по 7204, теряет живые матчи навсегда.

## 7. Инструменты

### `rig/` — пульт (основное)

Node 24 + Fastify + встроенный `node:sqlite` + SSE на бэке.
Vite + React 19 + TypeScript + Tailwind v4 + TanStack Table + GSAP + uPlot на фронте.

```bash
cd rig
npm install
npm run start      # сборка + сервер на http://localhost:4322
npm run dev        # разработка, фронт на 5173 с проксированием API
```

Что умеет:

- живой остаток жилы, лента отправок, графики роста счётчиков
- таблица своих гемов с сортировкой, каталог всех 53 с поиском и ссылками на покупку
- наборы с гемом со ссылками в магазин Dota
- **старт и остановка отправщика прямо из панели**, с выбором списка и темпа
- всё обновляется по SSE, браузер ничего не опрашивает

### `gcwatch/` — отправщик

```bash
node index.js --dry                                    вход по QR, сессия сохраняется
node index.js --ids build-team-empire.csv --send --delay 30000 --keep-alive
node index.js --ids ... --send --password              вход паролем вместо QR
```

Вход по QR через приложение Steam, сессия ложится в `token.json` — дальше запускается молча.
Переживает разрывы связи, отправленное пишет в журнал, темп меняется на лету через `delay.txt`.

`ids.js` собирает пары `match_id,league_id` из OpenDota:

```bash
node ids.js team 46 --out empire.csv
```

Пиши через `--out`, а не через `>` : PowerShell 5.1 сохраняет в UTF-16.

### `gemtrack.js` — независимый замер

Снимает счётчики из публичного инвентаря и сравнивает срезы. Нужен как проверка, независимая
от панели.

```bash
node gemtrack.js snap 76561198362481819 T0
node gemtrack.js diff T0 T1
```

### `getreplay.js` — скачивание реплеев

Тянет с серверов Valve прямо в папку реплеев клиента. Valve отдаёт по адресу с расширением
`.dem.bz2`, но внутри давно **zstd** — из-за этого все старые гайды ломаются, инструмент
определяет сжатие по сигнатуре. `VERIFIED`

## 9. Ключи и ограничения

Ключи лежат файлами и **обязаны быть в `.gitignore`**:

- `opendota.key` — ключ OpenDota. Оплата поштучная, привязана карта
- `steam.key` — ключ Steam Web API
- `token.json` — сохранённая сессия Steam. Это ключ от аккаунта

Ограничения, на которые напоролись:

- **Steam отдаёт 429** на инвентарь при частом опросе, и уходит в отказ на минуты. Все обращения
  идут через одну очередь с паузой **2.5 секунды**. Уникальный параметр в URL, сбивающий кеш
  Steam, делает только хуже
- **Лимит на входы.** `RateLimitExceeded` ловится не за сообщения, а за частые логины. Отсюда
  режим `--keep-alive`: одна сессия на всю работу вместо входа на каждый тест
- **Одна клиентская сессия на аккаунт.** Бот выбивает десктопный Steam и наоборот. Пока идёт
  прожиг, Steam и Доту не открывать

## 10. Риски

Три разные вещи, которые часто путают.

**VAC — не при чём.** Сканирует память запущенного игрового процесса. Здесь игра не запускается.

**Экономический бан Steam — реальный вектор.** Ограничения выдаются за манипуляции с экономикой.
Подделка клиентского сообщения ради стоимости предмета попадает в эту категорию. Риск ненулевой,
и несёт его аккаунт с гемами.

**Откат счётчиков — самое вероятное последствие.** Не бан, а обнуление накрученного.

По масштабу: десяток сообщений с паузой в секунды — меньше трафика, чем клиент шлёт в меню.
Тысячи подряд на машинной скорости — это уже профиль, который видно.

Отдельно: `steam-user` — стороннее ПО, разговаривающее с сервисами Valve, и Steam Subscriber
Agreement такое запрещает. Легальная альтернатива с тем же результатом, но медленная —
просмотр реплеев в настоящем клиенте, там сообщение уходит само.

## 11. Открытые вопросы

1. **Переживает ли счётчик извлечение чиселом.** Единственный неотвеченный вопрос механики.
   Рынок намекает, что да — голые гемы торгуются со счётчиками до 168, — но с тех пор как
   выяснилось, что голый гем и сам умеет набирать, рыночные лоты доказательством не служат.
   Цена ответа: Artificer's Chisel, около $1.07, и это необратимо
2. **Сущности трёх гемов** — `CaspeRRR`, `VeRsuta`, безымянный. Работа по Liquipedia, не по API
3. **Считает ли гем студии её турниры или то, что она комментировала.** Первое измеримо
   (у Beyond the Summit 31 лига, у Dota Cinema две), второго нет ни в одном источнике
4. **Реакция Valve** — были ли прецеденты откатов, не выяснено

### Закрыто замерами 19–20 августа

- ~~Считается ли голый гем без сокета~~ → **считается**, см. 3.6
- ~~Точный потолок студийных гемов~~ → BTS **не 7740**, а порядка 3900–4200 в 31 лиге
- ~~Кто и почём покупает высокие счётчики~~ → снято по решению владельца проекта

### Ограничения, которые не снимаются

- **`7204` пуст по протоколу.** Дубль и отказ неразличимы в принципе, не только у нас
- **Valve отдаёт максимум 500 матчей на лигу.** Курсор ниже последнего даёт пусто,
  `date_min`/`date_max` игнорируются. Из 153 216 матчей в 1210 лигах доступно 130 872,
  то есть 85 %. Недостающие 22 344 сидят в 30 крупных турнирах и берутся только из зеркал
- **Зеркала теряют по-разному.** По Ohaiyo STRATZ дал 1916, OpenDota 1672, общих 1615.
  Ни один источник не полон — правда только в объединении

Относительная раскладка `rig/` и `tools/` сохранена намеренно: `server/paths.ts` ищет данные
по `../tools`, поэтому переименование этих двух папок сломает пути.

**Что осталось в `Desktop\Dota 2 market` — это DotaTrade**, к гемам отношения не имеет:
`index.html`, `serve.js`, `assets/`, `ext-ui/`, `ref/`, `.old/` и остальные утилиты в `tools/`,
которые режут графику клиента.

Старые копии файлов гем-проекта там тоже остались — переезд был копированием, не переносом.
Убедишься, что всё работает, и удалишь оттуда `rig/`, `tools/gcwatch/`, `tools/gemtrack*`,
`tools/getreplay.js`, `tools/gem-*.json`, `tools/gems.json`, `tools/rig.db`, `tools/panel.js`
и ключи.

### Быстрый старт

```bash
cd rig
npm install
npm run start
```

Панель на `http://localhost:4322`. Отправщик по умолчанию остановлен — пока не нажать
«Запустить» в первой карточке пульта, ни одно сообщение в GC не уходит.

Зависимости отправщика ставятся отдельно:

```bash
cd tools/gcwatch
npm install
```

## 13. Что делать дальше

Порядок такой, и он не переставляется:

1. **Проверить голый гем** — три цента и один матч в очередь. Определяет масштаб закупки
2. **Проверить спрос** — три-пять реальных сделок с ценой за высокий счётчик. Пока этого нет,
   всё остальное производит фантик
3. **Собрать состав гемов** — докупить всё, что хочешь набить, **до** прожига
4. **Жечь** — по одному списку на сущность, с запасом по темпу
