# Gemtrack — весь функционал

Опись без прикрас. Четыре раздела:

| раздел | что значит |
|---|---|
| **Есть** | написано, проверено на живых данных, работает сейчас |
| **Написано, но не проверено живьём** | код есть и тесты зелёные, но настоящего прожига не было |
| **Должно было быть, но нет** | обещал или подразумевалось — не сделано |
| **Будет** | решено делать, очередь известна |
| **Может быть** | предложения, решения нет |

Дата: 21 августа 2026. Тестов: 141 серверных + 139 отправщика.

---

## 1. Есть и проверено

### Движок

**Карта матчей.** Своя база: 305 427 матчей, 3 010 689 связей «игрок — матч»,
2 106 турниров. Собрана обходом Valve с добором из OpenDota там, где Valve
упирается в свой потолок 500 матчей на лигу. Расхождения с OpenDota нет.

**Журнал расхода по аккаунтам.** Матч расходуется у каждого аккаунта отдельно;
ключ составной `(аккаунт, матч)`. Развязка прошла на живой базе, 66 записей
приписаны первому аккаунту. Это было обязательным условием второго аккаунта:
раньше он унаследовал бы чужой расход и получил пустую очередь.

**Три состояния записи.** `confirmed` — GC прислал обновление. `dup` — ответил,
но без обновления. `silent` — не ответил, и это означает «не знаем», а не
«сожжён»: silent в журнал не пишется вовсе. `dup` не вычитается из остатка —
проверено 20 августа на матче 8003261364, он вернул dup и остался целым.

**Сборка очереди.** Матчи всех сущностей из инвентаря, минус израсходованное
этим аккаунтом, минус матчи без турнира (GC такое молча отвергает), слитые
без повторов, тяжёлые первыми. Сейчас: 11 580 матчей, из них 840 поднимают
сразу две сущности.

**Потолок по своей карте.** Считается по той же выборке, из которой строится
очередь. Таблица `supply` врала в обе стороны: у Ohaiyo показывала 0 при 1849
пригодных, у DD — 1017 при 568.

**Отправщик.** Отдельный процесс, вход по сохранённой сессии, персона Invisible,
пауза перечитывается из файла на ходу, журнал отправленного переживает
перезапуск, восстановимые ошибки различаются от фатальных, шесть попыток
переподключения с растущей паузой.

**Работник.** Раз в такт: смотрит инвентарь → состав изменился, пересобирает
очередь → очередь пуста, ждёт → отправщик мёртв, поднимает → молчит дольше
предела, перезапускает → пять падений подряд, встаёт с причиной. Решение —
чистая функция, проверяется тестами, а не по логам.

**Подбор паузы.** Пока GC отвечает на каждую отправку, темп растёт; появились
молчания — это потолок, отходим. Дубли темпом не считаются: они про матч,
а не про скорость. Читает настоящий отчёт отправщика.

**Разброс счётчиков.** Одно сообщение поднимает все подходящие вещи разом,
поэтому 29 предметов идут в ногу. Разные значения получаются только партиями:
счётчик вещи равен числу отправок после её появления. Работник считает моменты
и говорит, когда добавлять следующую партию — 1186 / 1096 / 1006. Круглые числа
не берутся вовсе: заказ 2000 превращается в 2408.

**Настройки.** Всё, что было константой: цель, такт, предел молчания, число
падений, срок инвентаря, шесть порогов подбора паузы, полоса и дрожание
разброса, глубина дерева. Значения зажимаются на сервере.

### Панель

Полотно на всю ширину, боковая колонка, переключение аккаунтов, семь экранов.
Оформление снято с osint-catalog.xyz числами из их сборки: фон `#0a0a0a` с шумом
в двенадцать сотых, поверхность белым в одну сотую, границы в шесть, прямые
углы, Geist, подписи не капсом, высота управления сорок пикселей.

| экран | что делает |
|---|---|
| **Работа** | запуск с целью и разбросом, четыре числа, плитка гемов, «требует внимания», журнал решений |
| **Мои гемы** | таблица по гемам с раскрытием до каждой вещи, вид «все вещи», разделение «самоцвет / на предмете», фильтр, поиск |
| **Граф** | дерево аккаунт → гем → турниры и сеть пересечений; панорама, зум, перетаскивание узлов, карточка узла |
| **Очередь** | что уйдёт и в каком порядке, вес каждого матча |
| **Лента** | отправки построчно с фильтром по результату |
| **Закупка** | каталог 53 гемов, потолок, дойдёт ли до цели, ссылка на рынок |
| **Аккаунты** | список, привязка по QR в окне, настройки аккаунта в окне, отвязка с предупреждением, переименование |
| **Настройки** | все пороги с объяснением, что каждый значит |

Данные идут одним потоком SSE, браузер ничего не опрашивает. Иконки настоящие —
хеш из инвентаря разворачивается в картинку Steam.

**Различение носителя.** Голый самоцвет продаётся как самоцвет и его можно
вставить в любой подходящий предмет; у предмета со вставленным счётчик
неотделим. Признак берётся из инвентаря: у голого собственное имя
`Spectator: X` и нет строки `Used By`. Сейчас: 51 вещь, из них один голый.

### Проверенные факты о механике

- голый самоцвет накапливает наравне с надетыми — Alliance 2 → 3 при трёх
  контрольных надетых 0 → 1
- гем считает матчи своей сущности, а не турнира — лига 14389: Empire +10,
  NaVi осталась на 5
- журнал аккаунта не истекает — пять матчей NaVi через 26 часов дали пять dup
- `league_id` обязателен: без него молчание, с ним 507 байт
- одно сообщение поднимает все подходящие вещи разом
- счётчик **не переживает** распаковку набора: набор на 4 → семь предметов по 0
- темп: 76 отправок в минуту при паузе в секунду, отклик GC 340 мс по медиане,
  465 мс на 95-м, 764 мс худший

## 2. Написано, но живьём не проверено

Код есть, типы сходятся, тесты зелёные — но настоящего прожига не было.
Пишу отдельно, чтобы не выдавать одно за другое.

| что | чем проверится |
|---|---|
| остановка на цели | один заказ на 100 отправок |
| смена паузы на ходу | прогон длиннее сорока отправок |
| привязка второго аккаунта по QR | один настоящий QR |
| два отправщика рядом | два включённых аккаунта |
| перезапуск по молчанию | убить процесс отправщика во время работы |
| подсказка «пора добавить партию» | прогон с разбросом на две партии |

## 3. Должно было быть, но нет

**Экран закупки как советчик.** Сейчас это таблица каталога. Обещал «что
докупить, чтобы получить больше товара» с расчётом и кнопкой «взять всё дешевле
десяти центов». Расчёт не написан.

**Скрипты в панели.** `crawl`, `merge-mirrors`, `remeasure`, `supply-report`,
`plan-purchase`, `status` — до сих пор команды в терминале, хотя должны быть
кнопками с видимым ходом работы. Сказал «строю», не построил.

**Таблица брака.** Отказ Valve не объясняет причину, их две: матч израсходован
этим аккаунтом или негоден сам по себе. С двумя аккаунтами различить можно —
не прошёл нигде, значит брак. Общей таблицы нет.

**Три неопознанные сущности.** CaspeRRR и ещё два гема не сопоставлены с
командой или игроком, поэтому в очередь не попадают. Лежат мёртвым грузом.

**Проверка счётчика после извлечения гема.** Не знаем, переживает ли счётчик
вынимание самоцвета из предмета. Для распаковки набора проверено — не
переживает; для извлечения — нет.

## 4. Будет

Порядок — по тому, что умножает выход.

**1. Прожиг с целью на сто отправок.** Проверить всё из раздела 2 за один
заход: остановку, подбор паузы, разброс. Дешевле сотни матчей ничего не стоит.

**2. Второй аккаунт.** Развязка журнала сделана, осталось привязать и запустить
рядом. Даёт вдвое больше товара за то же время.

**3. Экран закупки-советчика.** Считает, что докупить: копия уже жгущегося гема
стоит ноль отправок, новая сущность — полный прогон. Показывает выгоду в вещах
на доллар, а не в счётчиках.

**4. Таблица брака.** Появляется бесплатно, как только работают два аккаунта:
матч, не прошедший нигде, помечается и вычитается из всех очередей.

**5. Скрипты кнопками.** Обход, сверка зеркал, перемер — в панель, с полосой
хода и логом.

**6. Опознание оставшихся сущностей.** Три гема, чтобы не лежали зря.

## 5. Может быть

Предложения. Решения нет — записаны, чтобы не потерялись.

**План по цели.** «Хочу 100 вещей на 2000+» — система считает, что докупить,
сколько жечь, сколько это займёт и стоит.

**Учёт продаж.** Цена на рынке рядом со счётчиком, история продаж похожих
предметов, подсказка, когда выставлять. Продажу человек делает сам.

**Слепок и откат.** Снимок счётчиков перед прогоном, чтобы можно было показать
разницу «было — стало» за любой период.

**Расписание.** Жечь ночью, когда компьютер свободен; днём стоять.

**Оповещение.** Сообщение в телефон, когда цель достигнута или работник встал
с ошибкой.

**Своя раскладка гемов по предметам.** Показать, в какие предметы выгоднее
вставлять голые самоцветы — дорогая основа поднимает цену готового товара.

**Проверка перед покупкой.** Вставить ссылку на лот с рынка и сразу увидеть
потолок сущности, пересечения с уже купленным и цену за тысячу счётчиков.

**Второй показатель качества.** Кроме «дошёл до 2000» — разнообразие турниров
в истории вещи: счётчик, набранный по трёмстам разным турнирам, выглядит
естественнее, чем набранный по трём.

## 6. Чего система знать не может

Не «не сделано», а нельзя в принципе.

- **почему Valve отказала** — `CMsgUpgradeLeagueItemResponse` пустое по
  протоколу, у него нет полей. «Матч уже израсходован» и «сообщение отвергнуто»
  снаружи неразличимы
- **сколько вещей поднимается одним сообщением при большом их числе** —
  наблюдение есть только для четырёх объектов в 507 байтах
- **переживёт ли счётчик извлечение гема из предмета** — не проверялось
- **что Valve считает подозрительным** — правил нет, есть только наблюдаемое
  поведение
