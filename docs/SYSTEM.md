# Gemtrack — как работает система

Не список задач, а устройство. Что за объекты, что происходит само,
что требует человека, и что показывает панель.

---

## 1. Что производим

**Товар — это вещь со счётчиком 2000+.** Не счётчик, не гем, а конкретный
предмет в инвентаре, который можно продать.

Одна отправка в Valve поднимает **все** подходящие вещи разом. Поэтому:

```
2000 отправок Empire  →  1 вещь на 2000, если держишь одну
                      →  20 вещей на 2000, если держишь двадцать
                         отправок в обоих случаях 2000
```

Второй и двадцатый товар стоят **ноль отправок** — только цену гема, три цента.
Отсюда всё устройство системы: она оптимизирует не отправки, а **вещи на выходе**.

## 2. Объекты

```
АККАУНТ  ────────────────────────────────────────────
   steamid, метка, сохранённая сессия
   свой инвентарь
   свой журнал израсходованных матчей     ← ключевое
       │
       ├── ВЕЩЬ  предмет или голый гем, несёт счётчик
       │      принадлежит одному аккаунту
       │      привязана к сущности
       │
       └── РАБОТНИК  один на аккаунт, крутится постоянно
              очередь матчей — пересобирается сама
              темп
                  │
                  └── ОТПРАВКА  один матч
                         состояние: ждёт → ушла → засчитана / спорная / без ответа

СУЩНОСТЬ  ───────────────────────────────────────────
   команда или игрок
   пул матчей из локальной базы           общий для всех аккаунтов
   потолок = размер пула
```

**Прогона как объекта нет.** Была мысль сделать «прогон» — снимок состава,
старт, финиш. Она не выжила: гем, купленный посреди прогона, в такой снимок
не попадал, и человеку пришлось бы останавливать и запускать заново. Вместо
этого работник живёт всё время, а состав инвентаря и есть выбор.

**Пул матчей общий, журнал расхода — на каждом аккаунте свой.** Это главное
свойство системы: три аккаунта жгут один и тот же пул независимо и получают
втрое больше товара.

## 3. Что происходит само

Человек нажимает один тумблер — «работник включён». Дальше:

```
        каждые 20 секунд
                 ▼
        ┌─────────────────────────────────────────┐
        │  смотрю инвентарь                       │
        └────────────────┬────────────────────────┘
                         ▼
        ┌─────────────────────────────────────────┐
        │  состав изменился?                      │
        │    да  → пересобираю очередь            │
        │          матчи всех моих сущностей      │
        │          минус израсходованное МНОЮ     │
        │          слитые без повторов            │
        │          тяжёлые первыми                │
        └────────────────┬────────────────────────┘
                         ▼
        ┌─────────────────────────────────────────┐
        │  очередь пуста?   → жду новых гемов     │
        │  отправщик мёртв? → запускаю            │
        │  молчит минуту?   → перезапускаю        │
        │  пять падений?    → стоп с причиной     │
        │  иначе            → не мешаю            │
        └─────────────────────────────────────────┘
```

Внутри самого отправщика: отправка, пауза, ответ записан. Выбило десктопным
Steam — ждёт и входит заново. Связь упала — то же самое. Шесть отказов подряд —
останавливается с причиной.

**Человек нужен только чтобы купить гем.** Купил — работник заметит в течение
двадцати секунд, добавит его матчи в очередь и продолжит. Нажимать «пуск»
не надо, есть только «остановить».

**Без человека переживается:** обрыв связи, выбивание десктопным Steam,
перезапуск компьютера (журнал на диске), закрытие панели.

**Всё ещё за человеком:** купить гемы, распаковать наборы, забрать товар.
Распаковка — не лень системы, а свойство предмета: счётчик не переживает
разбор набора, проверено 19 августа на наборе с четвёркой.

## 4. Несколько аккаунтов

Три аккаунта — три независимых работника **одновременно**. Ограничение
«одна сессия» действует на аккаунт, не на машину.

```
аккаунт A   очередь 11 580   ─┐
аккаунт B   очередь 11 580   ─┼─  параллельно, 2,5 часа
аккаунт C   очередь 11 580   ─┘

один аккаунт    45 товаров
три аккаунта   135 товаров, то же время
```

Цена — гемы на каждый отдельно. Пул матчей не делится.

### Отсев негодных матчей

Отказ Valve не объясняет причину. Их две:

```
матч израсходован ЭТИМ аккаунтом  →  на других свежий
матч негоден сам по себе          →  не сработает нигде
```

С одним аккаунтом различить нельзя. С двумя — можно:

```
не прошёл на A, прошёл на B   →  причина аккаунтная
не прошёл ни на A, ни на B    →  матч в брак, исключить везде
```

Система копит общую таблицу брака и вычитает её из всех очередей.

## 5. Экраны

### Пульт — главный

Построен. Отвечает на вопрос «всё ли идёт нормально и что мне делать».

```
┌────────────────────────────────────────────────────────────┐
│  ( ●━ )  работник включён                    1с 2с 5с 30с  │
│          жгу очередь, 11 580 матчей                        │
├──────────┬──────────┬──────────┬───────────────────────────┤
│  11 580  │  2 ч 32  │  76/мин  │  4 с назад                │
│ в очереди│ до конца │   темп   │  последнее подтверждение  │
├──────────┴──────────┴──────────┴───────────────────────────┤
│  ТОВАР                          0 из 51 вещей за 2 000     │
│   BZZ    ×29   12 / 2 000   потолок 2 155 · осталось 2 148 │
│   ████░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░  │
├──────────────────────────┬─────────────────────────────────┤
│  ТРЕБУЕТ ВНИМАНИЯ        │  ЧТО ДЕЛАЛ РАБОТНИК             │
│  ● Ohaiyo не дойдёт      │  00:57  жду новых гемов         │
│  ● DD не дойдёт          │  00:56  очередь: 11 580         │
└──────────────────────────┴─────────────────────────────────┘
```

Три вещи, ради которых он такой.

**Тумблер, а не «пуск».** Запускать нечего: работа не имеет начала и конца,
она либо идёт, либо нет.

**Строка «последнее подтверждение».** Отвечает на «оно вообще живое?»
без изучения логов.

**Потолок считается по своей карте.** Раньше брался из таблицы supply,
и та врала в обе стороны: у Ohaiyo показывала 0 при 1849 пригодных,
у DD 1017 при 568. Панель обещала то, чего отправщик не сделает.

### Аккаунты

По каждому: инвентарь, счётчики, остаток, состояние сессии, кнопки.
Добавление нового — по QR-коду из приложения Steam.

### Закупка

Каталог 53 гемов, но не для изучения. Показывает **что докупить, чтобы
получить больше товара**, и даёт купить пачкой:

```
Empire      2594 матча    5 вещей   →  +10 вещей за $0.30  → +10 товаров
Alliance    2483          4         →  +10 за $0.40        → +10
```

Кнопка «взять всё дешевле десяти центов». Ссылки в Steam Market.

### Граф

Сущности узлами, рёбра — общие матчи. Видно, что покупать вместе выгодно:
Empire и BZZ делят 840 матчей, значит их прожиг обходится дешевле по отправкам.

## 6. Уровни автоматизации

```
БЫЛО            команда в терминале, один аккаунт
                выбор состава руками, список файлом

СДЕЛАНО         работник: тумблер, очередь строится сама
                купленный гем входит в работу без перезапуска
                отправщик поднимается сам, если упал

ДАЛЬШЕ 1        несколько аккаунтов параллельно
                журнал расхода на каждом свой
                общая таблица брака

ДАЛЬШЕ 2        экран закупки: что докупить и почему
                кнопка «взять всё дешевле десяти центов»

ДАЛЬШЕ 3        план по цели: «хочу 100 товаров на 2000+»
                система сама считает, что докупить и сколько жечь
```

Динамическая очередь была отдельным уровнем в старом плане — она уже
внутри работника, отдельным этапом её больше нет.

## 7. Что система знает и чего не знает

**Знает точно:**
- сколько матчей у каждой сущности — 305 427 матчей в своей базе
- какие израсходованы на этом аккаунте
- сколько вещей несёт каждый гем
- сколько времени займёт очередь — 76 отправок в минуту, измерено

**Не знает и знать не может:**
- почему Valve отказала — ответ пустой по протоколу
- переживёт ли счётчик вынимание гема из вещи
- сколько вещей поднимается одним сообщением при большом количестве

**Знает неточно:**
- потолок трёх гемов, чья сущность не опознана
- около 3 % матчей, которые есть у четвёртого источника данных

## 8. Порядок работ

```
✓ Пульт на один аккаунт          главный экран, тумблер, прогресс
✓ Динамическая очередь           купленный гем входит сам
  Экран закупки                  что докупить и почему
  Журнал расхода по аккаунтам    развязать перед вторым аккаунтом
  Несколько аккаунтов            параллельные работники
  Таблица брака                  отсев негодных матчей
  Граф пересечений               визуализация выгоды
```

Пульт даёт работающий инструмент на один аккаунт. Развязка журнала и
второй аккаунт умножают выход втрое в то же время.

### Что осталось в терминале

`crawl`, `merge-mirrors`, `remeasure`, `supply-report`, `plan-purchase`,
`status` — команды, а должны быть кнопками с видимым ходом работы.
Это следующий заход после экрана закупки.
