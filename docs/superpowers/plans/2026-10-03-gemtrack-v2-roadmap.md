# Gemtrack v2 — дорожная карта

> Карта этапов, а не пошаговый план. Подробный план каждого PR пишется скиллом
> `superpowers:writing-plans` в начале работы над ним — по коду, каким он будет к тому моменту.
> Первый подробный план: `2026-10-03-c0-market-rate-limit.md`.

**Спецификация:** `docs/superpowers/specs/2026-10-03-gemtrack-redesign-design.md` (коммит `7ae1ef1`, 1 023 строки).
**Исходная точка кода:** ветка `design/gemtrack-v2`; тесты сервера — 25 файлов, 343 теста, все проходят
(`cd rig && npm test`, своя база в памяти — живой `rig.db` не трогают).

## Правила для всех этапов

- Один PR — одна задача; своя ветка от актуального `master` (или от предыдущего PR, если зависит).
- Серверные изменения — **сначала тест, потом код**.
- **Живой сервер `rig` для проверки не запускать никогда** — только тесты и демо-сборка
  (`cd dash && VITE_DEMO=1 npx vite --port 5180`, конфигурация `dash-demo`).
- Инварианты §14 спецификации важнее всего остального. Нарушение — повод остановиться и спросить.
- Цель счётчика — только `settings.goal`. Живое значение уже `1000` (`tools/settings.json`, проверено
  2026-10-03) — задача С1 выполнена.
- Новая панель живёт **в той же сборке `dash` за переключателем**: по умолчанию старая, новая — по адресу
  с `?ui=v2` (выбор запоминается). Обе ходят в один API. **В конце новая становится единственной,
  старая удаляется целиком** (решение владельца, 2026-10-03).
