# Этап 2.1: экран «Обзор» — план

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Цель:** вместо заглушки «Обзор» в `?ui=v2` — рабочий экран по §5.1 и макету `1-obzor.html`: холст «аккаунт → гемы → вещи», режим «сеть матчей», инспектор выбранного гема, тревоги с действиями, KPI в верхней полосе.

**Как устроено:** холст — SVG-рёбра и HTML-узлы на фиксированной сетке, как в макете, с вписыванием в видимую область и зумом. Данные — `state.mine`, `state.autopilot`, `/api/settings` (цель), `/api/graph` (сеть). Логику не пишем заново: «не дойдёт», «нет в карте» — те же условия, что в `attention()`.

**Стек:** React 19, без новых зависимостей. Только демо (`VITE_DEMO=1`), живой `rig` не запускается.

**Спецификация:** `docs/superpowers/specs/2026-10-03-gemtrack-redesign-design.md` — §3 (правила), §4.3 (клавиатура), §5.1 (Обзор), §5.7 (колокольчик), §6 (данные). Макет: `…/2026-10-03-gemtrack-redesign/1-obzor.html`. Дорожная карта: этап 2.1 (без режима «список» — этап 8; порядок колокольчика — здесь).

## Global Constraints

- §3.1 без прыжков; §3.2 цель только из `settings.goal` — в макете `1 000` и `GOAL = 1000` зашиты, в коде их нет; нет цели — прогресс и «не дойдёт» не рисуются, вместо них «цель не задана».
- §3.3 четыре состояния значения; у оценочных — метка `оценка`.
- §3.4 действия, меняющие работу, — только кнопкой человека; «Накрутить» — как в этапе 1.
- §3.5 цифры Geist + `tabular-nums`; steamid — Geist Mono.
- §4.3 узлы гемов — кнопки: `Tab`, `Enter`/`Space`; стрелки ↑/↓ двигают выбор между гемами; смысл не только цветом (у «не дойдёт» / «нет в карте» — слово-чип, у рёбер — легенда со словами); у кнопок зума — подписи.
- `prefers-reduced-motion`: без бегущих импульсов и появления веера.
- Старая панель не меняется; общий код (`lib/worker.ts`) — только добавлением, не меняя выводов старой панели.
- Проверка — демо + те же приёмы, что на этапе 1 (ширины, прокрутка, «без прыжков», источник цели).

## Решения, которые нужно сверить до кода

1. **Действия у тревог (§5.1).** Сервер умеет только одно из трёх:
   | Кнопка в §5.1 | API | На этапе 2.1 |
   |---|---|---|
   | «снизить цель до N» (у «не дойдёт») | `POST /api/settings {goal}` | **есть** — через окно подтверждения: цель общая для всех гемов и аккаунтов, меняет «готово» и план закупки |
   | «не считать товаром» | нет (`aside` — про отдельную вещь из прихода, не про гем) | **нет кнопки**; в тревоге — «что делать» текстом |
   | «указать команду» (у «нет в карте») | нет (правки карты гемов через API нет) | **нет кнопки**; текстом, как сейчас |
   Две недостающие — серверные доработки; в дорожную карту не добавляю без решения владельца.
2. **«только этот гем» в инспекторе** → `POST /api/autopilot {id, only: [гем]}`. Контракт — `OBSERVED` по коду (2026-10-04), живым запуском не проверялся:
   - `rig/server/index.ts:173–190`: `if (b.only !== undefined) patch.only = b.only` → `setAutopilot(id, patch)`; `id` — из тела, по умолчанию активный аккаунт;
   - `rig/server/autopilot.ts:572–577`: массив → `u.only = only.map(String).filter(Boolean)`; `null` — «все»; пустой массив — «ничего»; `u.fingerprint = ''` — очередь пересобирается;
   - `autopilot.ts:169–177` (`picksFor`): жжёт только гемы инвентаря, чьё голое имя (`p.key`, то же, что `state.mine[].gem`) есть в `only`; гем не из карты — жечь нечего («выбранные гемы ничего не дают»);
   - `autopilot.ts:458–461`: в состоянии `only` и `picked` (что реально жжётся);
   - старая панель шлёт то же: `parts/Tune.tsx:104–114` — `send({ only: list | null })`, «все» = `only: null`.
   Действует **на один аккаунт**. Через короткое подтверждение («работник этого аккаунта будет жечь только X; вернуть все — «Настроить» → «все»»).
3. **Режим «сеть матчей».** §5.1: «нынешний режим `Graph.tsx`». Встраивать старый компонент нельзя без чужого вида (цвета зашиты: `#0a0a0a`, `#f4f4f5`). Предлагаю **перенести** его режим `Net` (и помощников `useCanvas`, `Zoomer`, `Label`) в `src/v2/Network.tsx` с токенами v2, логику раскладки (`lib/force.ts`) не трогать. Это временная копия до этапа 9, где старый `Graph.tsx` удаляется. Режим «дерево» старого `Graph.tsx` (гем → турниры) — **другое дерево**, в Обзор не переносится.
4. **«готово к продаже» в KPI.** **Новый KPI «готово к продаже» рассчитывается по каждой вещи** (`rows[].value >= goal`) — как его определяют §5.1/§5.2 и макет («готово к продаже X / N» по вещам); **старый расчёт** (`Work.tsx`: все вещи гема, если `max >= goal`) **не изменяется**. Расхождение между старым и новым экраном **допустимо на этапе миграции и не является ошибкой само по себе**. Старая панель заморожена до этапа 9 — расхождения не повод её править.
5. **Колокольчик (замечание ревью этапа 1):** порядок §5.7 — красные → «не дойдёт» → справочные. Для этого `attention()` получает **необязательное поле `kind: 'reach'`** у тревог «не дойдёт» — добавление поля, вывод старой панели не меняется.

## Принято по ходу (сверка задачи 3, 2026-10-04)

- **Решение по интерфейсу (не из спецификации):** «только этот гем» **неактивна** у гема со статусом «нет в карте» — рядом объяснение. Контракт `only` такой гем принял бы, но работнику нечего было бы жечь, и работа аккаунта встала бы. §5.1 кнопку требует; отключена она намеренно, а не забыта.
- **Окно «снизить цель»** говорит: «от цели считаются „готово к продаже“, „не дойдёт“ и план закупки». Для плана закупки — `OBSERVED` по коду: `rig/server/api.ts:456–459` (`marketScan` берёт `settings().goal`), `:521` (`rank(offers, goal)` → `market.ts:107–111`, `reaches = pool >= goal`), `market.ts:129–135` (`plan()` пропускает `!reaches`), `api.ts:526` (доп. отправки от цели). Других потребителей цели этим утверждением не охватываем и без проверки не расширяем.
- Действия у тревог — только под инспектором; колокольчик — текст.

## Задачи

### Task 1: статус гема и порядок колокольчика
- [ ] `gemStatus(m, goal)`: `'map'` — `!m.entityId || !m.kind || m.kind === 'unknown'`; `'reach'` — `goal != null && m.supply != null && m.supply < goal`; иначе `'ok'`. Условия — дословно из `attention()`.
- [ ] `attention()`: у тревоги «не дойдёт» — `kind: 'reach'`. Больше ничего не менять.
- [ ] `Bell`: сортировка stop → reach → прочие (стабильная).
- [ ] Проверка: текст старого Пульта = снимок «до»; колокольчик на демо: «не дойдёт» (Ohaiyo, DD) перед CaspeRRR.

### Task 2: холст «дерево»
- [ ] Раскладка как в макете: аккаунт слева → столбец гемов → веер вещей выбранного (до 5, при > 5 — 4 + «ещё N — в инвентаре»), подпись ребра «N вещей · +1 за матч».
- [ ] Порядок гемов: в работе → не дойдёт → нет в карте; внутри — по счётчику вниз.
- [ ] Узел гема: иконка, имя, «max / цель» (нет цели — «max · цель не задана»), полоса, вторая строка — герой и вещей или чип («не дойдёт» / «нет в карте»).
- [ ] Рёбра: обычные серые; работник идёт и гем в работе (`ap.picked`) — лайм со свечением и импульсом; «не дойдёт» — жёлтый пунктир; «нет в карте» — красный пунктир. Легенда словами.
- [ ] Узел аккаунта: имя, steamid, лампа работника, вещей / гемов / сожжено (`ap.burned`).
- [ ] Зум +/−/вписать, вписывание при смене размера; узлы гемов — кнопки, ↑/↓ двигают выбор.
- [ ] Выбор — кольцо внутрь (§3.1); наведение — только фон.

### Task 3: инспектор и тревоги
- [ ] Инспектор: иконка, имя, «герой · вещей, надето», чип статуса; кольцо `max / цель`; факты: разброс `min–max`, осталось до цели, дойдёт ли (`да` / `нет` / `неизвестно` при `supply == null`, с меткой `оценка`, если `supplyKind === 'estimated'`); до 5 вещей с «надето»; кнопки «только этот гем» (п. 2) и «в инвентаре» (переход на экран).
- [ ] «Требует внимания» под инспектором: `attention()` в порядке Task 1; у «не дойдёт» — «снизить цель до {supply}» через окно подтверждения (что изменится; цель общая); остальные — текст.

### Task 4: сеть матчей
- [ ] Перенос `Net` из `views/Graph.tsx` в `overview/Network.tsx`: цвета — токены v2; раскладка, зум, панорама, подписи — без изменения логики; `lib/force.ts` не трогать.
- [ ] Переключатель «дерево / сеть матчей» в шапке экрана; данные — `/api/graph` через `Loadable` (≤ 8 с).

### Task 5: KPI и проверка
- [ ] KPI в полосе: вещей, гемов, в очереди, готово к продаже (п. 4), инвентарь «N назад» (устарело — серее).
- [ ] Демо: 1440 / 1280 / 1000 / 700 — без прокрутки, «без прыжков» по узлам и кнопкам, «Накрутить» видна; источник цели (`settings.goal = 1000` / `autopilot.goal = 2000`); без цели; закрытый инвентарь; ↑/↓/Enter; reduced-motion — правило в CSS.
- [ ] `npm run check`, `npm run build`; старая панель = снимок «до»; PR, CI, мёрдж после сверки.
