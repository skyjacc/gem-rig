## Решения, которые нужно сверить до кода

1. **Демо-данные для Скупки.** В снимке нет разбора площадки, хода закупки и прихода — без них в показе экран проверяется только в пустых состояниях. Предложение: отдельный файл **`dash/src/demo/buy.json`** — **составленный руками, не записанный с сервера**, в точной форме ответов `/api/market`, `/api/arrivals` и `PurchaseRun`; читает его **только** v2-Скупка при `DEMO` (без правки `lib/api.ts` и `canned()`, старая панель его не видит). В файле — поле `"_note": "составлено руками для показа…"`; полоса показа и так подписана «ничего не отправляется». Вариант без файла: проверяем только «нет данных / ошибка», вёрстку конвейера и ленты — нет. Ещё одно: в снимке `settings` нет `purchaseCap`, `perGem`, `priceTolerance` — в показе потолок «не задан», пока его не подставит временный снимок; в коде отсутствие поля = «не задан», не ноль и не выдумка.
2. **Бюджет и потолок.** «Бюджет — он же потолок суммы» (§5.3) на сервере — это `settings.purchaseCap` (`vetLines`: без потолка закупка не начинается, сумма выше — отказ). Предложение: поле «бюджет» — **локальное**, для «собрать план» (пустое = `min(потолок, баланс)`; **отличие от старой**: там пустое = весь баланс, и план выше потолка сервер всё равно отверг бы); рядом **потолок из настроек** только для чтения, «изменить» открывает существующее окно правил. Новых записей настроек со Скупки нет.
3. **С8 — когда кнопка «Запустить закупку» активна.** Только если одновременно: разбор площадки есть и без ошибки; **`key.state === 'ok'`**; валюта показа = валюте счёта; `purchaseCap > 0` и корзина ≤ потолка; корзина не пуста; закупка не идёт. Иначе кнопка неактивна, под ней **первая причина словами** (тексты — те же, что ответил бы сервер). Баланс < суммы — предупреждение, но кнопку не блокируем: баланс в ответе кешируется на 30 с, окончательно его проверяет сервер. По статусам ключа:
   | `key.state` | плашка «Закупка на» | действие |
   |---|---|---|
   | `ok` | «ключ этого аккаунта · проверен N мин назад» | — |
   | `unchecked` | «ключ не проверен» | «проверить ключ» → `POST /api/accounts/market-key/check`, затем перечитать разбор |
   | `missing` | красная: «нет ключа — сервер не даст запустить» | пояснение: ключ задаётся в Аккаунтах (экран — этап 2.4) |
   | `mismatch` | красная: «ключ другого Steam ({marketSteamid}) — лоты ушли бы не сюда» | «проверить ещё раз» |
   | `invalid` | красная: «площадка отвергла ключ: {error}» | «проверить ещё раз» |
   Важно для сверки: сервер (`buyKey`) перепроверяет ключ сам при запуске; проверка в панели — подсказка заранее, не защита.
4. **Лента покупок** — из `state.purchase.log` (новые сверху), две цены — `price` и `planned`. Значки по `reason`: `куплено` ✓; `цена выросла` / `цена ушла` / `нет лотов` ↑ «позиция брошена»; `отказ` ↻ **«повтор N из 3»**; `нет денег` / `неясно` / `остановлено` — стоп, `detail` подсказкой. **N** в журнале не хранится — считаем из ленты: подряд идущие `отказ` одного гема в пределах текущего запуска, `N = ((k − 1) mod 3) + 1` (сервер после трёх отказов подряд уходит к другой позиции и при возврате считает заново — `purchase.ts`, `after()`). Ограничение: лента — последние 60 записей; если начало серии отрезано, N может быть меньше. Число 3 — константа с ссылкой на `after()`.
5. **Приход в Steam** — из **доступных строк** `/api/arrivals`: фильтр `account` = аккаунт закупки и `ts ≥ startedAt`; чипы «чисто / наш / выигрыш». Метка источника — `журнал` (приход — вкладка Журнала, §5.6). Нет закупки — узел показывает «—».
   **Ограничение источника (сервер не меняем):** `arrivalsOf()` (`arrival.ts:181`) отдаёт не больше 400 строк всей таблицы, без фильтра по аккаунту и времени, и сначала — все `выигрыш`, потом остальные по времени. Значит, часть подходящих строк может не попасть в выдачу, и число — **нижняя граница**. Подпись: «≥ N · по последним строкам прихода; не только купленное — всё новое на аккаунте с начала закупки». Без слова «всё пришедшее».
6. **«Общих с моими» — число и аватарки.** Число — **только `overlap` сервера** (§5.3: сумма по парам графа завышает). Аватарки «с какими моими» — из `edges` `/api/graph?scope=all`, где второй конец — мой гем (до 3, по `shared`), с меткой `граф`. Если граф не пришёл — число без аватарок.
7. **«Доп. время»** — `sends` сервера; главная цифра «+N мин» (= `sends / 76`), под ней «N отправок», метка `оценка`; подсказка расшифровывает: «min(потолок, цель) − общие = отправки; при 76 в минуту это N мин». У гема в работе — «бесплатно · уже крутится».
8. **План:** порядок по умолчанию = порядок «собрать план» (в работе → больше общих → дешевле тысяча → дешевле лот, только `reaches`) — перенос `optimal()` из старого `Buy.tsx:212–236` без изменения правил; фильтры «дойдут до цели / без отправок / все» и поиск — как в старой; диапазонов и сортировки по столбцам нет (в §5.3 их нет). Степпер «− N +» от 0 до `min(volume, perGem)`; во время закупки заблокирован.
9. **Запуск — новое окно `dash/src/v2/buy/BuyConfirm.tsx`.** Готовое `ActionDialog` (`v2/Dialog.tsx:13`, им пользуются Тревоги и Инспектор) **не берём**: оно закрывается по Esc и по фону, а его же комментарий оговаривает, что так можно всем окнам, «кроме необратимого запуска». Закупка тратит деньги необратимо, поэтому окно ведёт себя как `ConfirmBurn` (§5.7 для «Накрутить»): закрывается **только кнопками**, фокус заперт в окне и стоит на «отмене». Внутри — строки корзины, «спишется до X», аккаунт, допуск цены. Тело запроса — как в старой Скупке (`lines`, `id` аккаунта разбора, `currency`); ошибка сервера — в окне, окно не закрывается. *Это перенос правила §5.7 с «Накрутить» на закупку — в §5.3 оно прямо не написано.*
10. **Тип `PurchaseRun`** в `lib/api.ts` — добавить необязательное `account?: { id: string; label: string } | null` (только тип, поведение старой панели не меняется).
11. **Цель на Скупке — `scan.goal`**, то есть `settings().goal`, которой сервер считал этот разбор (`api.ts`, `marketScan`); это то же `settings.goal` (§3.2), только ровно та, по которой посчитаны `reaches`, `per1000`, `sends`. Сервер ограничивает цель 1..100 000 (`settings.ts:94`), разбор без цели не бывает — **состояния «цель не задана» на Скупке нет**. Если `/api/settings` в панели не пришёл, Скупка всё равно берёт цель из разбора; нет разбора — нет и плана (`Loadable`).
12. **Чего нет:** имитации «показать, как идёт закупка» из макета (в настоящей панели выдуманных событий не бывает); покупки в гривне (площадка не торгует — показ только для прикидки, кнопка неактивна по правилу валюты); KPI полосы — те же, что у Обзора (`OverviewKpi`), как на 2.2.
