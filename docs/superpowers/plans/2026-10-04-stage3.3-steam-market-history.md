# Этап 3.3: история рынка Steam (С4) → журнал операций — план

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Цель:** продажи вещей и покупки ключей на рынке Steam попадают в журнал операций (`money_ops`, этап 3.1) поштучно — с ценой покупателя, комиссией Steam, комиссией игры и тем, что пришло на кошелёк, **из истории рынка, а не пересчётом** (§16).

**Как устроено:** как в 3.1 — сначала **живое чтение формата вместе с владельцем**, потом разбор по наблюдённому смыслу, потом импорт. Чтение истории — под веб-сессией аккаунта (`webCookieHeader()` в `steamweb.ts`, уже есть, нигде не вызывается). Куки живут только в памяти процесса.

**Стек:** Node 24, `node:sqlite`, `node:test`. Без новых зависимостей. Панель не меняется (экран Продаж — этап 2.6).

**Спецификация:** §7 С4 («до реализации проверить на живом аккаунте, что `steam-session` выдаёт куки нужного домена и что формат ответов такой, как ожидаем»), §13 (риск платформы), §14, §15 («продажа на рынке Steam, комиссии — история рынка Steam»), §16 (определения сумм). Дорожная карта: этап 3.3 («на одном живом аккаунте проверены куки и формат (с участием владельца); исторические суммы не пересчитываются»).

## Global Constraints

- **Сервер: сначала тест, потом код.** `cd rig && npm test` — все тесты зелёные; `npm run check`.
- Живой `rig` не запускается. Чтение Steam — только разовым скриптом (задача 1) или по запросу (`POST`), не по таймеру.
- **Куки сессии не печатаются, не пишутся на диск, не попадают в журнал, `raw_ref`, ошибки и логи** (§14 п. 4). Сырой ответ Steam — только вне репозитория: в нём личные суммы и номера.
- Деньги — целыми в мелких единицах валюты кошелька, с валютой; никаких float и **никакого пересчёта** комиссий из цены (§16: «из истории рынка, не пересчётом»).
- Журнал операций — тот же `money_ops`: `source = 'рынок Steam'`, одна внешняя операция — одна запись, записи не меняются (кроме однократной `reconciled_at`), исправление — сторно.
- Только чтение у Steam: ничего не выставляется, не снимается, не покупается.

## Риск платформы (§13) — на решение владельца

Факт (`VERIFIED`, SSA, §13 спецификации, перепроверено на сверке 2026-10-04): соглашение Steam запрещает скрипты, ботов и макросы для взаимодействия с сервисами Steam.

**`RISK / INTERPRETATION`:** автоматизированное чтение собственной истории рынка под своей веб-сессией, вероятно, подпадает под эту широкую формулировку (§4.C SSA). Точную юридическую квалификацию именно такого запроса — только чтение, ничего не меняет в аккаунте, не даёт игрового прогресса — мы не утверждаем. Чем реже и мягче — тем незаметнее: только по запросу, малыми страницами, с паузами, с остановкой на первом 429. Этап в дорожной карте уже согласован; здесь это записано, чтобы решение было явным, а не молчаливым.

## Сессии: пара токенов (решение сверки 2026-10-04)

**Что выяснилось при первой попытке.** Обмен сохранённого токена на веб-куки дал `AccessDenied` — и у старого токена, и у свежего после перепривязки (выдан 2026-10-04 18:12 UTC, действует до 2027-05, `sub` = steamid аккаунта). Причина — не отзыв: в документации `steam-session` (1.9.4, `node_modules`; та же формулировка на npm) сказано, что **с 2025-04-30 `getWebCookies()` и `refreshAccessToken()` для `EAuthTokenPlatformType.SteamClient` вне аутентифицированной CM-сессии отвечают `AccessDenied`**; для `WebBrowser` `getWebCookies()` поддерживается (а `refreshAccessToken()` — нет). `VERIFIED` (документация библиотеки, 2026-10-04).

Следствия:
- `checkSession()` в `steamweb.ts` с тех пор для любого SteamClient-токена говорит «revoked» — **ложный отрицательный результат**;
- куки через нынешний `webcookies.js` (платформа SteamClient) получить нельзя.

**Архитектура — две разные учётные записи, не заменяющие друг друга:**

| Токен | Платформа | Файл | Для чего | Как проверять |
|---|---|---|---|---|
| игровой (есть) | `SteamClient` | `tools/gcwatch/token.json` (и `token-<id>.json`) | отправщик, GC | только сам клиент (`steam-user`) при входе; `refreshAccessToken()` вне CM — не годится |
| веб (новый) | `WebBrowser` | `tools/gcwatch/token-web-<id>.json` (закрыт `.gitignore`: `token-*.json`) | чтение `steamcommunity.com` (история рынка) | фактическим `getWebCookies()`; `refreshAccessToken()` — не годится |

Игровой токен и игровая сессия не трогаются: веб-вход — отдельный QR, отдельный файл.

**Состояния сессии — раздельно** (вместо одного «ok / revoked»):
- `validUntil` — срок из самого токена (поле `exp` JWT), известен локально; **неистёкший ≠ действующий** — отзыв так не проверяется;
- `client` — состояние реального SteamClient-входа: подтверждает только сам клиент (отправщик); до отдельной работы — «не проверено»;
- `web` — проверяется только фактическим получением веб-кук веб-токеном.

`checkSession()` для SteamClient-токена больше не говорит «revoked»: отвечает `unknown` с пояснением «проверка этим методом для SteamClient-токена недоступна (Steam, 2025-04-30)» и `validUntil`. Значения состояния — из существующего набора (`unknown`), поэтому замороженная старая панель показывает его нейтрально, без правки (§ правила: старая панель не меняется).

## Решения, которые нужно сверить до кода

1. **Живое чтение — задача 1, до разбора.** Сумма, номер, валюта и типы событий фиксируются по наблюдённому ответу и закрепляются в плане (раздел «Проверено вживую»), без сумм, номеров и названий вещей.
2. **Что пишется в деньги** (кандидаты; окончательно — после задачи 1):
   - продажа вещи → «продажа вещи»: `gross` — цена покупателя, `fee_steam`, `fee_game` — как в ответе, `net = +пришло`;
   - покупка ключа Mann Co. → «покупка ключа»: `gross` — уплачено, `net = −уплачено`;
   - прочие покупки, выставление и снятие лота, всё непонятное — `skipped` с причиной (в §16 нет типа «прочая покупка»; лот без продажи — не движение денег).
3. **Без пересчёта:** если в ответе нет одной из сумм — поле `null`, а не «посчитано из ×1,15»; запись в деньги идёт только при наблюдённом `net`.
4. **`externalId()`** — заменяемая функция, как в 3.1; в схеме `money_ops` ничего не меняется.
5. **Частота** — свой ограничитель для `steamcommunity.com`: не чаще 1 запроса в 3 секунды на аккаунт, на 429 — остановка импорта до следующего запроса человека (без повторов), страница — не больше 100 строк. Цифры — наша осторожность, не факт Steam.
6. **Импорт** — `POST /api/money/steam-sync {id, pages?}`: страницы от новых к старым, пока не встретится уже записанная операция или не кончится лимит страниц (по умолчанию 3, не больше 20). Повторный импорт ничего не добавляет.
7. **Куки** — только `webCookieHeader(a)` в памяти, **из веб-токена** (`WebBrowser`); отказ Steam — понятная ошибка, без попытки входа; игровой токен для веба не используется.
8. **Чего нет в 3.3:** ключей TF2 и времени их освобождения (С5, этап 3.4), экрана Продаж (2.6), курсов валют, автоимпорта.

### Предложения на сверку (до задачи 2)
