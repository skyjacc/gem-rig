# Этап 3.4: ключи TF2 — на руках, на удержании, когда можно передать (С5) — план

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Цель:** сервер знает, сколько ключей Mann Co. лежит на аккаунте, сколько из них ещё нельзя передать и **точное время**, когда каждый станет передаваемым, — по каждому `assetid`, из Steam, не оценкой (§5.4, §7 С5).

**Как устроено:** как в 3.1 и 3.3 — сначала **живое чтение формата вместе с владельцем**, потом разбор по наблюдённому смыслу. Инвентарь TF2 (appid 440) читается **веб-сессией аккаунта** (веб-токен `WebBrowser`, этап 3.3): у владельца в ответе есть строки, которых нет у постороннего, — среди них, по спецификации, `Tradable After: …`. Это **состояние**, не деньги: ключи не пишутся в `money_ops`, а хранятся снимком по `assetid`.

**Стек:** Node 24, `node:sqlite`, `node:test`. Без новых зависимостей. Панель не меняется (экран Продаж — 2.6).

**Спецификация:** §5.4 (ключи: на руках · на hold · можно передать; время — точное, UTC, по каждому `assetid`; пока С5 нет — оценка «покупка + 7 суток» с меткой), §7 С5, §13 (риск), §14 п. 4, §15. Дорожная карта: этап 3.4 («время из Steam, не оценка; куки сторонних сайтов не используются»).

**Порядок работы:** сверка по этапу целиком (решение 2026-10-04): план → одобрение → все задачи → один PR → CI и рецензия → мёрдж по «мёрдж #N». Живые действия — только по отдельному «да» владельца.

## Global Constraints

- Сервер: сначала тест, потом код; `cd rig && npm test`, `npm run check`.
- Чтение Steam — только по запросу (разовый скрипт или `POST`), не по таймеру; не чаще 1 запроса в 3 с на аккаунт, на 429 — стоп без повторов.
- Куки — только веб-токена (`webCookieHeader`), только в заголовке; не печатаются, не пишутся на диск, не попадают в базу и логи. **Куки сторонних сайтов (`clover_session` и т. п.) не используются** (§7 С5).
- Сырой ответ Steam — только вне репозитория (`C:\Users\oblako\gemtrack-private\`).
- Время — UTC в мс; строка Steam хранится как есть рядом (в подсказке экрана §5.4 нужна исходная строка).
- Только чтение у Steam: ничего не передаётся, не продаётся, не выставляется.

## Что известно (до живого чтения)

| Факт | Статус |
|---|---|
| Steam пишет время освобождения строкой `Tradable After: Sunday, October 4, 2026 (7:00:00) GMT` | `OBSERVED` (пример владельца, спецификация 2026-10-03) |
| эта строка есть в `owner_descriptions` инвентаря под куками владельца, запрос с `l=english` | спецификация; **вживую не проверено** → `HYPOTHESIS` |
| публичный инвентарь (`/inventory/<steamid>/570/2?l=english`) читается без кук — так сейчас читается Dota (`steam.ts`) | `OBSERVED` (работающий код) |
| `IEconItems_570/GetPlayerItems` отдаёт `flag_cannot_trade` и атрибут 427 (дата трейд-кулдауна) | `VERIFIED` для Dota (README §3.5); **для TF2 (`IEconItems_440`) не проверено** |
| hold ключа ≈ 7 суток от покупки | `HYPOTHESIS` (спецификация); точное время — только из Steam |
| время покупки ключей — в журнале операций (`money_ops`, «покупка ключа», этап 3.3) | есть |

## Решения, которые нужно сверить до кода

1. **Источник времени — инвентарь TF2 под веб-куками** (`/inventory/<steamid>/440/2?l=english&count=…`): у каждого ключа (`market_hash_name = Mann Co. Supply Crate Key`) — `tradable` и строка `Tradable After: …` в `owner_descriptions`, если она есть. Запасной источник — `IEconItems_440/GetPlayerItems` (атрибут 427, `flag_cannot_trade`) — **только если** живое чтение покажет, что строки в инвентаре нет; ключ Web API (`steamKey()`) уже есть и в адрес не попадает в логи. Решение — после задачи 1.
2. **Разбор строки** `Tradable After: <день недели>, <Месяц> <число>, <год> (<ч>:<мм>:<сс>) GMT` → метка UTC; строгий разбор (формат ровно как наблюдён, `l=english`); не разобралось — «время неизвестно», не угадываем.
3. **Полнота инвентаря.** Инвентарь читается страницами (`count` до 2000, `start_assetid` из `last_assetid` ответа, как у Dota в `steam.ts`), пока Steam сообщает продолжение (`more_items`), — не больше 5 страниц. Если продолжение есть, а лимит кончился, или страница вернула ошибку, — **снимок не сохраняется**: ответ «снимок неполный: …». Первые 2000 молча за весь инвентарь не выдаются.
4. **Модель — снимок как отдельная сущность** (только вставка, правка и удаление запрещены триггерами, как в 3.1):
   - `tf2_snapshots`: `id`, `account_id`, `seen_at` (UTC мс), `complete` (всегда 1 — неполный не пишется), `keys` (сколько ключей);
   - `tf2_keys`: `snapshot_id` → `tf2_snapshots.id`, `assetid`, `tradable` (0/1 как в ответе), `tradable_after` (UTC мс или NULL), `tradable_after_raw` (строка Steam или NULL); уникальность `(snapshot_id, assetid)`.
   «Последний снимок» аккаунта — с наибольшим `id`, а не по совпадению времени.
5. **Состояние каждого ключа** (функция, без сети) — по двум признакам, с явным противоречием (§3.3: расхождение видно, молча не выбирается):
   | `tradable` | `tradable_after` | состояние |
   |---|---|---|
   | 1 | нет | можно передать |
   | 1 | в будущем | **расходится** (Steam говорит «можно», но время ещё не наступило) |
   | 1 | в прошлом | можно передать |
   | 0 | в будущем | на удержании до времени |
   | 0 | в прошлом | **расходится** (время прошло, Steam ещё не отпустил — снимок мог устареть; перечитать) |
   | 0 | нет | на удержании, время неизвестно (оценка — решение 6) |
6. **Итог** (функция, без сети): `onHand` — ключей в последнем снимке; `tradableNow`, `held`, `conflict` — по таблице решения 5 (каждый ключ ровно в одном); `nextRelease` — ближайшее будущее `tradable_after` у удержанных и сколько ключей тогда освободится; группы по одинаковому времени (§5.4); `seenAt` снимка — чтобы экран мог сказать «устарело».
7. **Когда точного времени нет** (ключ `tradable = 0`, строки нет) — время `NULL` и признак «оценка доступна»: оценка «время покупки + 7 суток» считается **отдельно** и помечается `оценка` (§5.4), из `money_ops` по ближайшей покупке ключа — это решение экрана 2.6; в 3.4 — только функция оценки с меткой, не запись в снимок.
8. **Маршрут** — `POST /api/keys/sync {id}` (чтение инвентаря страницами, куки на сервере после проверки параметров, через ограничитель Steam 1 запрос / 3 с; 429 — стоп без повторов) и `GET /api/keys?id=` (итог из последнего снимка, без сети).
9. **Чего нет:** экрана (2.6), тревоги «ключи можно продавать» (колокольчик — 2.6), продажи ключей и площадок (этап 4), инвентаря других аккаунтов (3.5).
