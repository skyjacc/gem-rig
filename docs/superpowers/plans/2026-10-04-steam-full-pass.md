# Полный проход истории рынка Steam — план (малый PR)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Цель:** загрузить в журнал операций всю историю рынка Steam, а не только последние страницы, — не сломав ежедневный импорт.

**Почему отдельно:** это меняет смысл синхронизации. Ежедневный импорт (`steamSync`, этап 3.3) останавливается на первой уже записанной сделке — так он не листает всю историю каждый раз. Исторический проход должен идти дальше. Два режима — явно, чтобы случайно не сломать обычный.

**Стек:** как в 3.3. Сервер: сначала тест, потом код. Панель не меняется.

## Решения

1. **Режим** — `mode: 'новые' | 'полный'`, по умолчанию `'новые'` (поведение 3.3 без изменений).
   - `'новые'`: стоп на первой уже записанной сделке, конце истории, лимите страниц, 429, ошибке — как сейчас.
   - `'полный'`: **не** останавливается на записанном; стоп — конец истории, лимит страниц, 429, ошибка. Повторы не вставляются (`UNIQUE(source, external_id)`), считаются в «уже было».
2. **Начало** — `from` (номер первой записи, кратный 100, по умолчанию 0) — **только для режима «полный»**; в режиме «новые» ненулевой `from` → ошибка без запроса (иначе обычная синхронизация незаметно станет частичным проходом).
   **`next`** — откуда продолжить:
   - страница обработана → `next = start + 100` (при «лимите страниц» — за последней обработанной);
   - 429, ответ не 200, не JSON, без `success` → `next = start` этой же страницы: она **не обработана**, продолжать с неё, а не со следующей;
   - конец истории → `next = null`;
   - режим «новые» дошёл до записанного → `next = null` (этот режим не продолжают).
   **Ограничение (принято):** `from` — смещение, а не курсор. Если между запусками полного прохода появятся новые сделки, старые страницы сдвинутся на столько же записей; повторы база не пустит, но запись на стыке может оказаться пропущенной до следующего полного прохода. Для текущей истории (~1100 записей, один запуск ≤ 20 страниц) это не мешает; для истории больше 2000 записей — отдельная задача на устойчивый курсор.
3. **Лимит страниц, пауза, 429** — без изменений: 1..20 страниц, не чаще 1 запроса в 3 с на аккаунт, на 429 — стоп без повторов и пауза 10 мин.
4. **Маршрут** — `POST /api/money/steam-sync {id, pages?, mode?, from?}`; неизвестный `mode` → ошибка, без обращения к Steam.
5. **Живой полный импорт** — только после мёржа и отдельного «да» владельца: история сейчас около 1100 записей → один запуск `mode: 'полный', pages: 20` (≈ 11 страниц, ≈ 35 с).
