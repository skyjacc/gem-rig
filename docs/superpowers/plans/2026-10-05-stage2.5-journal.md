## Решения, которые нужно сверить до кода

1. **«Подняло ≈ N вещей» — не по формуле байт, а точным числом отправщика.**
   - Формула §5.6 `N ≈ round((bytes − 29,5) / 67,5)` выведена из двух точек README (97 байт — одна вещь, 907 — тринадцать). Арифметика сходится, но точки сняты **с консоли игрового клиента**, а наше `bytes` — длина тела msg 26 в отправщике (`payload.length`, `index.js:405`) — другая точка измерения. И старый отчёт отправщика (22 августа, 40 отправок) противоречит формуле: ответы по 6 010 байт дали бы ≈ 89 вещей при ≈ 51 вещи на аккаунте тогда. Третий пример README (507 байт) формулу не проверяет: там записаны счётчики двух гемов, а не число вещей. Статус формулы — `CONFLICT`.
   - **Предлагаю (вариант Б):** сервер сохраняет точное `so.econModified` новым необязательным полем события `items` (колонка `events.items`, `NULL` у старых записей; миграция при старте, как прочие). Экран показывает «изменено вещей: N» без метки «оценка» — это число из ответа GC, а не догадка. У старых событий (`items` нет) — «—» с причиной «до этапа 2.5 не записывалось», байты — как есть.
   - Что `econModified` = «вещи, у которых сдвинулся счётчик», — `HYPOTHESIS`: msg 26 может менять у вещи и другое. Поэтому подпись буквальная — «изменено вещей (ответ GC)», без «подняло счётчик». Сверка с инвентарём — вживую, после мёржа и по «да» владельца.
   - Вариант А (без сервера): формула §5.6 с меткой `оценка` и пометкой «калибровка с консоли клиента». Не рекомендую — см. противоречие выше.

2. **Пульс** — последние 240 отправок `state.events` (больше сервер не отдаёт), по времени слева направо, каждая — черта цвета ответа (засчитан — акцент, спорный — жёлтый, без ответа — серый пунктир; у каждой — подсказка словом). Черта — кнопка: выбирает отправку справа. Подпись «последние N отправок» — не «все».

3. **Плитки.**
   - «засчитано» и «спорных» — **за всё время** по таблице `burned`: предлагаю добавить в ответ `/api/burned` счёт по состояниям `byState: { confirmed, dup, ledger, reconstructed }` (один `group by`, без изменения прочих полей). Без этого — только по последним 240 событиям, с подписью окна.
   - «спорных» дополнительно расшифровывается из `state.dups`: ждут повтора · брошены · засчитались со второй.
   - «сожжено на аккаунте» — `state.burned`; «в очереди» — `/api/queue` `total` и «из них по два гема» — `weight2`.

4. **Вкладки** (переключаются без перезагрузки, выбранная — в адресе не хранится):
   - **Отправки** — пульс + список: время, матч (`v2-id`, ссылка `https://www.opendota.com/matches/<id>`), лига, ответ словом, байты, «изменено вещей» (решение 1). Фильтры: все · засчитаны · спорные · без ответа — со счётчиками.
   - **Очередь** — `/api/queue?limit=300`: матч, лига, гемы чипами с иконками (иконка — из `state.mine`/`catalog`, как на Скупке), ×2. Пояснение: «двойные первыми — один матч поднимает два гема сразу».
   - **Израсходовано** — по гему из `/api/tree`: всего матчей, сожжено, осталось (`state.mine`), полоска; крупнейшие турниры гема полосками (`value`, `burned`), не больше `settings.treeTop`.
   - **Приход** — `/api/arrivals`: вердикты (чисто · наш · выигрыш), фильтр, «отложить / вернуть» (тот же `POST /api/arrivals/aside`, что в старой панели); пустое состояние — с легендой вердиктов.
   - **Решения** — журнал работника активного аккаунта (`action` · `why`, время), новые сверху.

5. **Имя лиги** у отправки — из уже загруженных `/api/tree` (узлы `kind: league`, id вида `<гем>:<лига>`) и `/api/burned` (`leagueName`); не нашлось — номер лиги. Новых запросов ради имени нет.

6. **Демо.** Предлагаю `dash/src/demo/journal.json` — **составлен руками** (`"_note"`): ответы `/api/burned` (с `byState`) и `/api/arrivals`, `state.dups`, несколько событий `silent` и событий с `items`. Читает только v2-Журнал при `DEMO`; старая панель и `canned()` его не видят — как `buy.json`, `accounts.json`.

7. **Правая колонка:** выбранная отправка (все поля, ссылка OpenDota, «изменено вещей» или почему нет); «как читать ответы» — засчитан = msg 26, единственное подтверждение; спорный = 7204 без msg 26, неотличим от дубля, из остатка не вычитается; без ответа — GC промолчал, матч не помечается сожжённым; последнее подтверждение (`state.confirmed`, «N назад»). Ничего не выбрано — подсказка «выберите отправку в пульсе или списке».

8. **Чего нет:** диагностики (§19 — отдельно); истории глубже 240 событий; правки чего-либо, кроме «отложить» в приходе; журнала других аккаунтов, кроме активного (данные сервера — по активному).
