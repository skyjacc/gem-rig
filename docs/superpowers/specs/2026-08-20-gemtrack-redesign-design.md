# Gemtrack — редизайн панели

Дата: 2026-08-20
Статус: на ревью
Заменяет: панель «Жила» (`rig/`), одностраничную панель (`_legacy/panel.js`)

---

## 1. Зачем

Панель строилась вокруг одной сущности и одного большого числа. После аудита и замера
20 августа выяснилось три вещи, которые ломают эту модель:

1. **Голый гем без сокета набирает счётчик.** Замер: `Spectator: Alliance` 2 → 3 при трёх
   контрольных предметах 0 → 1. Artificer's Chisel не нужен, и коллекция теперь собирается
   россыпью из гемов по $0.03, а не поштучно через чиселы по $1.07.
2. **Остаток, который показывает панель, неверен.** Он считается по таблице `burned`,
   замороженной на девяти записях из двадцати трёх, и покрывает 5 сущностей из 53.
3. **Часть справочных чисел — фантомы.** У десяти гемов-игроков в `gem-map.json` стоит
   `matches_estimate` от 1321 до 2117 при `confidence: VERIFIED`, а измеренный набор матчей
   пуст. Суммарно 15 442 несуществующих матча, среди них Ohaiyo, чьих предметов на аккаунте семь.

Работа панели сместилась: раньше это был пульт прожига одной жилы, теперь — каталог из
53 гемов, из которого надо решать, что докупить, и очередь, из которой надо жечь.

## 2. Цели

- Одно полотно под 1920×1080: таблица слева, живой рельс справа, без вкладок-режимов
- Все числа честные: остаток из измеренных наборов, фантомы помечены, оценки подписаны
- Голый гем, предмет с сокетом и нераспакованный набор различимы в интерфейсе
- Очередь из нескольких сущностей со слиянием пересечений
- Обновление интерфейса без ожидания кеша Steam
- Интерфейс на английском

## 3. Не цели

- Публикация наружу. Инструмент локальный, авторизации и мультипользовательности нет
- Мобильная вёрстка. Целевая ширина 1920, минимальная поддерживаемая 1440
- Автоматический запуск прожига. Отправка всегда начинается с явного действия человека
- Решение вопроса спроса на высокие счётчики. Это отдельная задача, панель на неё не влияет

## 4. Визуальная система

Референс `osint-catalog.xyz` разобран: собственного CSS у него нет. Токены `--background`,
`--foreground`, `--card`, `--popover`, `--primary`, `--secondary`, `--muted`, `--accent`,
`--destructive`, `--border`, `--input`, `--ring`, `--chart-1…5` при `--radius: .625rem` —
стоковый **shadcn/ui** с нейтральной палитрой без правок. Анимации — `enter` / `exit` из
`tailwindcss-animate`. Значит визуальный язык воспроизводится установкой публичных пакетов,
а не копированием.

| Слой | Что берём |
|---|---|
| CSS-фреймворк | Tailwind v4 — **уже стоит** в `rig/` |
| Компоненты | shadcn/ui, нейтральная база, `--radius: .625rem` |
| Анимации | `tailwindcss-animate` |
| Шрифты | Geist Sans, Geist Mono; Inter на вкладке Graph |
| Иконки | lucide-react (идёт с shadcn) |

Своё — приёмы, не файлы:

- **Ведущие нули** в числовых колонках: `01`, `05`, `00`, `2 340`. Держат колонку ровной
- **Плотная строка фильтров** в одну линию над таблицей
- **Один набор данных, несколько видов** переключателем верхнего уровня

Логотипы, маскот и шрифтовые файлы референса не используются.


Вкладки — **виды над одним набором**, не режимы. Фильтр, сортировка и поиск общие и
переживают переключение. Рельс справа живой на любой вкладке.

| Вкладка | Что показывает |
|---|---|
| **Table** | 53 гема, все колонки. Рабочая лошадь |
| **Cards** | Плитка с иконками для закупки глазами |
| **Graph** | 37 узлов с непустыми наборами, рёбра — общие матчи |
| **Bundles** | 15 наборов из магазина Dota, идущих уже с гемом |
| **Burn log** | Сожжённые матчи: дата, сущность, ответ GC, состояние записи |

### Колонки Table

| Колонка | Смысл | Источник |
|---|---|---|
| `Gem` | Имя без префикса `Spectator:` | `gems.json` |
| `Kind` | team / player / studio / league / unknown | `supply.kind` |
| `Items` | `3 + 1◇ + 2▣` — предметы, голые гемы, наборы | инвентарь, по `market_hash_name` |
| `Count` | Счётчики через точку, по убыванию: `12 · 04 · 00` | инвентарь |
| `Supply` | Размер измеренного набора; `no data`; `est. N` для оценок | `entity_matches` |
| `Burned` | Сожжено этим аккаунтом из набора | `burned ∩ set` |
| `Left` | `Supply − Burned` | вычисляется |
| `Price` | Цена лота на Steam Market | `gems.json` |
| `$/1k` | `price / supply × 1000` — цена тысячи счётчика | вычисляется |

`Supply` различает три состояния и никогда их не смешивает: измеренное число, `no data`
для пустого набора, `est. N` для оценки без измерения. Сейчас все три показываются
одинаково, и в этом источник фантомов.

### Различение носителей

Счётчик несут три разных объекта, и они больше не сливаются:

| Знак | Что | Как определяется |
|---|---|---|
| без знака | предмет с сокетом | `market_hash_name` не начинается с `Spectator:` |
| `◇` | голый гем | `market_hash_name` начинается с `Spectator:` |
| `▣` | нераспакованный набор | имя есть в `gem-bundles.json` |

Все три тикают одинаково — подтверждено замерами. Различать надо, потому что у них
разная цена, разная ликвидность и разный смысл при закупке.

## 7. Журнал как автомат

Локальный журнал только помнит. Арбитр — GC.

```
матч в очереди
     │ отправлен
     ▼
  ответ GC
     ├── msg 26 + 7204  →  update  →  state = confirmed,  счётчики +1
     ├── 7204 без 26    →  dup     →  state = confirmed,  счётчиков нет
     └── тишина         →  silent  →  НИЧЕГО НЕ ПИШЕТСЯ, матч остаётся доступным
```

Три правила, каждое закрывает найденный дефект:

1. **`silent` не пишет в журнал.** Сейчас пишет, и один зависший ответ навсегда исключает
   целый матч. Пока конвейер не работал, дефект спал; 20 августа конвейер заработал
2. **`reconstructed` отправляется наравне со свежими.** Верная догадка стоит одной отправки
   и переходит в `confirmed`. Ошибочная приносит счётчик и переходит в `confirmed` через `update`
3. **`dup` подтверждает сожжение.** Журнал сходится к правде через работу

Оговорка: `CMsgUpgradeLeagueItemResponse` — **пустое сообщение**, проверено по протоколу
Valve. 7204 не несёт результата, поэтому `dup` и «матч отвергнут» снаружи неотличимы.
Практического вреда нет: оба означают «счётчика не будет», и оба закрывают матч. Но в
`Burn log` они пишутся как `dup` без утверждений о причине.

## 8. Очередь

**В очередь кладутся сущности, разворачиваются в матчи при запуске.**

Сборка списка:

1. Взять наборы всех сущностей очереди
2. Объединить без повторов
3. Вычесть `burned` со `state IN ('confirmed','ledger')`; `reconstructed` **оставить**
4. Отсортировать по числу обслуживаемых сущностей, по убыванию
5. Отдать отправщику одним файлом

Пункт 4 — единственная нетривиальная часть. Матч, входящий в наборы трёх сущностей из
очереди, поднимает три гема одним сообщением. Отправлять такие первыми значит получать
максимум счётчика на сообщение и, если прогон прервать, прерваться на самом дешёвом остатке.

Измеренные пересечения владеемых сущностей:

```
BZZ ∩ Empire      209      NaVi ∩ Empire      164
NaVi ∩ Alliance   118      Empire ∩ Alliance   94
BZZ ∩ NaVi         64      BZZ ∩ Alliance      46
```

Очередь из четырёх владеемых сущностей — NaVi, Team Empire, Alliance, BZZ:

```
сумма наборов          9 890
уникальных             9 195      экономия 695 сообщений, 7,0 %
минус сожжённое        9 172      столько сообщений реально уйдёт
начислений счётчика    9 855      на 683 больше, чем сообщений

вес матча:  2 сущности —   683 матча
            1 сущность  — 8 489 матчей
```

Максимальный вес здесь **2**: ни один матч не обслуживает три сущности сразу, потому что
крупные пересечения у этих четырёх только парные. Сортировка по весу поэтому даёт не
кратный выигрыш, а аккуратный порядок: 683 двойных матча уходят первыми, дальше одиночные.
Экономия в 695 сообщений возникает не от сортировки, а от слияния — она была бы и без
порядка. Порядок нужен для того, чтобы прерванный прогон обрывался на дешёвом хвосте.

**Живой пересчёт.** Сгорел матч — остаток уменьшается у всех сущностей, чьи наборы его
содержат, а не только у текущей.

## 9. Realtime

Инвентарь Steam кеширован минутами и отдаёт 429 при частом опросе. Поэтому не одна петля, а три.

| Уровень | Когда | Источник | Что делает |
|---|---|---|---|
| **Мгновенно** | секунды после матча | `status.json` → `fs.watch` → SSE | счётчики подопытных гемов +1, помечены `pending`; лента и остаток обновляются сразу |
| **Сверка** | ~20 с после `update` | один запрос инвентаря | `pending` заменяется фактом; расхождение остаётся видимым |
| **Дежурный** | раз в 60 с | инвентарь | ловит изменения извне: покупки, продажи, ручное |

Все обращения к Steam идут через существующую очередь с паузой 2.5 с. При 429 —
пауза 5 минут, состояние помечается устаревшим, интерфейс это показывает, а не молчит.

Связка `status.json → events → burned` проверена на живом прогоне 20 августа и работает.
Ранее она не была сломана — она ни разу не запускалась.

## 12. Тестирование

Тестов в проекте нет ни одного. Заводятся вместе с редизайном, минимально но по-настоящему:

**Парсер** — фикстуры на реальной разметке Steam, снятой 20 августа: голый гем, предмет
с сокетом, набор, счётчик с запятой, счётчик без имени сущности, русская локаль,
kills-гем, пустой `descriptions`. Проверено вручную — коллизий `classid_instanceid` нет,
три набора с разными счётчиками имеют разные `instanceid`.

**Сборка очереди** — на синтетических наборах: слияние без повторов, вычитание журнала,
сохранение `reconstructed`, сортировка по весу.

**Автомат журнала** — `update / dup / silent` дают ожидаемые переходы; `silent` не пишет.

**Расчёт остатка** — SQL против эталона, посчитанного питоном по `_sets.pkl`.

Что тестами не покрывается и покрыто быть не может: поведение GC. Оно проверяется только
отправкой, и каждая отправка необратима.

## 13. Что закрыто замерами 20 августа

Три вопроса, которые могли обрушить модель, проверены и закрыты.

**Голый гем набирает счётчик.** `Spectator: Alliance` 2 → 3 при трёх контрольных предметах
0 → 1, сторожа неподвижны. Одно сообщение подняло четыре объекта с двумя разными базами.
Artificer's Chisel не нужен. `FACT`

**Гем считает сущность, а не лигу.** В лиге 14389 у Empire один матч, у NaVi — десять.
Сожгли матч Empire из этой лиги: Empire 1 → 11, BZZ 0 → 10, **NaVi остался 5**. Будь охват
лиговым, NaVi обязан был тикнуть. Пул сущности — это пул сущности. `FACT`

**Аккаунтный журнал не истекает.** Пять матчей NaVi, сожжённых 26 часами ранее, отправлены
повторно: пять ответов 7204, ноль обновлений, счётчик не двинулся. Потолок реален, доить
одну сущность бесконечно нельзя. `FACT`

Побочно: метод реконструкции журнала подтверждён — GC согласился, что все пять
восстановленных матчей действительно сожжены.

## 13a. Запас измерен с недобором

Числа `Supply` — **пол, а не потолок**. Четыре подтверждённые утечки:

| Утечка | Замер | Затрагивает |
|---|---|---|
| Гемы-игроки с закрытой историей матчей | Ohaiyo: endpoint даёт 0, ростер Titan показывает ≥302 | 7 предметов на аккаунте + 10 гемов каталога |
| Фильтр `lobby_type === 1` режет турнирные лобби типа 2 | DD теряет 45, BZZ — 0 | 26 гемов-игроков |
| У команды бывает несколько `team_id` | Alliance: второй id `626763`, +16 матчей | 21 гем-команда |
| Шесть гемов вне измерения вообще | BTS оценён в 7 740, не проверен | студии, лиги, неопознанные |

Что проверено и потерь **не** дало: командные наборы полны — OpenDota отдаёт ровно то,
что в базе (Alliance 2340, Empire 2413, NaVi 2704, совпадение до штуки).

Отсюда: перемер запаса выносится в отдельный этап плана. До него интерфейс обязан
показывать `Supply` как нижнюю границу, а не как факт.
